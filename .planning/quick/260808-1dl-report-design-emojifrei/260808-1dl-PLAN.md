## Reihenfolge im Card-Body

Foto → Name + ID → Rasse · Geschlecht · Alter → Pärchen / Interessenten →
Labels → Beschreibung Verhalten (`reason`) → Beschreibung Gesundheit (`health_note`)
→ Fußzeile mit Standdauer und Steckbrief-Link.

## Task 1: Farbtabellen

**files:** `catfinder.py`

`RATING_META`: `emoji` raus, dafür drei Farbwerte je Kategorie — `color` (Fläche,
Kante, Rahmen), `text` (abgedunkelt, für Text auf Weiß), `on` (Schriftfarbe im
gefüllten Label). Die Schriftfarbe wird **fest hinterlegt statt zur Laufzeit aus der
Helligkeit gerechnet** — vier Werte, die sich nicht ändern.

`HEALTH_META`: von zwei auf vier Einträge, damit der Negativfall („Keine Erkrankung
bekannt") und der Fehlerfall („Gesundheit unbekannt") unterscheidbar sind. `order`
bleibt in `RATING_META`, `_card_sort_key` bleibt unverändert.

## Task 2: HTML_TEMPLATE

**files:** `catfinder.py`

CSS komplett ersetzen, Header-Titel ohne Emoji. Achtung: Template wird mit
`.format()` gefüllt, alle CSS-Klammern müssen verdoppelt bleiben.

## Task 3: Card-Renderer

**files:** `catfinder.py`

`_render_card` auf die neue Reihenfolge umbauen. `_interested_badge` und
`_partner_line` wandern in eine gemeinsame Zeile unter Name/Meta. `_health_line`
wird zu `_health_label` (Chip) plus `_health_note` (Fließtext im Kategorieton).
Neuer Zweig: ist `rating == "geeignet"` und `health == "keine"`, wird **ein**
Label „Geeignet und gesund" gerendert statt zweier grüner.

Sektions-Überschriften und Empty-States ohne Emoji.

## Task 4: Filterleiste

**files:** `catfinder.py`

`_build_filter_bar`: Buttons ohne Emoji, typografisch (unterstrichen statt gefüllt),
Slider-Optik an das Papier angepasst. **Die Filterlogik bleibt unangetastet** —
gleiche IDs, gleiche `data-*`-Abfragen, gleiche Zustandsvariablen.
